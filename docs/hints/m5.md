# M5 hints

## MergingIterator

1. After `Next()` on the smallest child, what's the cheapest way to find the new smallest?
2. Keep a vector of children plus `current_` index. With a heap: a min-heap
   by `key()` of *valid* children. `Next()` advances the top child, then
   re-sifts it: pop_heap, advance, push_heap if still valid. Linear scan is
   the alternative, simpler and often faster for ≤ 8 children.
3. Any child that becomes invalid with `!status().ok()`: record the first
   error, and stop (become invalid). `Seek`/`SeekToFirst` reposition every child and rebuild the heap.

## DBIter

1. For a stream of internal keys sorted (user asc, seq desc), how do you
   yield each user key's newest visible entry exactly once?
2. `FindNextUserEntry(skipping, skip_key)`: loop over internal entries, and
   ignore those with `seq > snapshot`. If the entry is a deletion, set
   `skip_key` = its user key and skip everything with that user key. If it's
   a value and not skipped, stop here. On `Next()`: save the current user
   key as `skip_key`, and continue.
3. `key()` returns a view of the *user* key (strip 8 bytes). `Seek(target)`:
   seek the internal iterator to `LookupKey(target, snapshot).internal_key()`.

## Flush and the background thread

1. What must be true before the old WAL can be deleted?
2. When `mem_` exceeds `write_buffer_size` (checked on the write path): if
   `imm_` is still being flushed, wait (condition variable). Otherwise
   `imm_ = mem_`, create a new WAL + memtable, and signal the background thread.
3. The background thread copies `imm_`, drops the mutex, and builds the
   table into `NNNNNN.dbtmp`. Then Sync, rename to `NNNNNN.sst`, SyncDir.
   It re-locks, clears `imm_`, and deletes the old WAL. **Rename matters in
   M5**: at open, every `*.sst` is L0, so a crash must never leave a partial
   file with that name.

## Recovering last_sequence without a MANIFEST

1. After a flush deletes the WAL, where does the knowledge of "the highest
   sequence number ever used" live?
2. Only in the SSTables. On open, you need the max sequence across all L0
   tables and the WAL replay. Scan each table's entries, or add a
   `strata.max_sequence` property in the TableBuilder, which is cheaper.
   Write an ADR. This is exactly the kind of state M6's MANIFEST exists to hold.

## Snapshots

1. How does the DB know the oldest sequence any live snapshot needs?
2. Keep a `std::multiset<SequenceNumber>` under the mutex. `GetSnapshot`
   inserts and returns `shared_ptr<const Snapshot>` with a custom deleter
   that erases (locking the mutex). Careful: the deleter runs on whichever
   thread drops the last reference, possibly one already holding the mutex.
3. `ReadOptions::snapshot` → use its sequence instead of `last_sequence`.
   Flush keeps every version (compaction is where versions drop, M6).

## ScanRange (C++20 ranges)

1. What does `std::ranges::input_range` require of `begin()`, `end()`, and the iterator?
2. The iterator needs `value_type`, `difference_type`, `operator*` returning
   `pair<string_view,string_view>` by value, `operator++` (prefix and
   postfix-void), and `operator==(std::default_sentinel_t)`. Move-only, since
   it holds a `unique_ptr<Iterator>`. `begin()` may be called once (an input range).
3. `static_assert(std::input_iterator<ScanRange::iterator>)` in `range.h`.
   Compose-ability: `ScanRange` must be movable, so `views::take` can wrap it
   (an `owning_view`). Check `status()` after the loop.
