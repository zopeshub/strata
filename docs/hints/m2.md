# M2 hints

## Internal key comparator

1. Compare user keys first. When they're equal, which of two sequence
   numbers should come *first*?
2. The trailer is `fixed64((seq << 8) | type)`, so comparing trailers as
   integers, **descending**, orders by sequence descending, then type descending.
3. `r = user_cmp(ExtractUserKey(a), ExtractUserKey(b)); if (r != 0) return r;`
   then compare the decoded trailers, with larger first. `ParseInternalKey`
   fails on inputs shorter than 8 bytes or types > 1.

## WriteBatch::ForEach type erasure

1. `ForEach` is a template (accepts any lambda), but its loop lives in the
   .cc file. How can a non-template function call an arbitrary callable?
2. Pass `void* ctx = &fn` plus a plain function pointer that knows the real
   type: `[](void* c, const BatchOp& op) { (*static_cast<Fn*>(c))(op); }`.
   A captureless lambda converts to a function pointer. This is what
   `function_ref` (C++26) does.
3. `ForEachImpl(thunk, ctx)` walks the rep: skip the 12-byte header, loop
   `count` times reading the tag + varstrings, build `PutOp`/`DeleteOp`
   views into `rep_`, and call `thunk(ctx, op)`. If fewer or more ops are
   present than `count`, that's `Corruption`.

## Memtable on std::map

1. You want `std::map<std::string, std::string, Cmp>`, but `Get` has a
   `string_view`. What makes `map::find` accept a different key type without
   constructing a `std::string`?
2. A comparator with `using is_transparent = void;` and `operator()`
   overloads accepting `string_view` enables heterogeneous `lower_bound`.
   Wrap the `InternalKeyComparator`.
3. `Get(lookup)`: `it = map.lower_bound(lookup.internal_key())`. If
   `it != end` and `ExtractUserKey(it->first) == lookup.user_key()`, the
   entry's type decides between the value and `KeyDeleted`. Otherwise the
   result is `KeyAbsent`. Order of keys guarantees `it` is the newest visible version.

## Log writer

1. Track `block_offset_` (0..32767). How many payload bytes fit in the
   current block after a header?
2. Loop: `left = kBlockSize - block_offset_`. If `left < kHeaderSize`,
   zero-fill `left` bytes and set `block_offset_ = 0`. Otherwise
   `avail = left - kHeaderSize`, `n = min(avail, remaining)`. The type is
   FULL/FIRST/MIDDLE/LAST depending on (begin, end). Emit the fragment. Keep
   looping while bytes remain; do at least one iteration so empty records work.
3. Emit: header = CRC(4) len(2) type(1). CRC =
   `Mask(Extend(type_crc[type], payload))`. Append header then payload; then
   `block_offset_ += 7 + n`. Initial `block_offset_ = dest_length % kBlockSize`.

## Log reader

1. Separate "read the next physical record from the block buffer" from "assemble logical records".
2. `ReadPhysicalRecord` refills a 32 KiB buffer when it has fewer than 7
   bytes. A short read means EOF. It then parses a header, checks that the
   length fits, and checks the CRC. It returns the type, or a special
   `kEof` / `kBadRecord`. On `kBadRecord`, clear the whole buffer: you
   can't trust anything else in this block.
3. `ReadRecord` state machine with `in_fragmented_record`:
   - FULL: return it.
   - FIRST: start a scratch buffer.
   - MIDDLE/LAST without FIRST: report and drop.
   - FIRST/FULL while in a fragmented record: report the partial, then restart.
   - EOF mid-fragment: return nullopt silently (torn tail).
   - Unknown type: report and drop.

   Test each rule against `tests/m2/log_test.cc`'s names.

## DBImpl::Open / Recover

1. List the directory. Which files matter in M2? In what order must WALs be replayed?
2. Create the dir if `create_if_missing` (otherwise `InvalidArgument` if
   missing). Take the LOCK *before* reading anything. Parse every name.
   Replay `*.log` files in ascending number: each record is a WriteBatch;
   insert its ops into the memtable with sequence `batch.Sequence() + i`; set
   `last_sequence = max(...)`. Then open a new WAL with number `max + 1`,
   and **SyncDir** so its name survives power loss.
3. `error_if_exists`: "exists" means a WAL is present (in M6: CURRENT).
   Keep the old WALs in M2 (their data lives only in the memtable).
   `Write` with `sync=true`: append the record, then `Sync()` it, before
   applying to the memtable. The prefix property needs that order. Why?

## Destroy

1. It must fail if the DB is open. What mechanism already tells you that?
2. A missing directory is OK: return OK before trying to lock. Otherwise lock
   (`Busy` → propagate), delete every file whose name `ParseFileName`
   recognizes except LOCK, release the lock, delete LOCK, and remove the
   directory only if it is now empty. Foreign files are not yours to delete.
