## Fixed-width encoding (`util/coding.cc`)

1. What does `memcpy` of a `uint32_t` produce on a little-endian machine,
   and on a big-endian one? What do you need to do differently on the second?
2. `if constexpr (std::endian::native == std::endian::little)` lets one
   code path be a plain `memcpy`, and the other `std::byteswap` then `memcpy`.
   Both compile to one instruction on modern compilers. Check with `-O2 -S`,
   or on Compiler Explorer.
3. Encode: `v = std::endian::native == little ? v : std::byteswap(v); memcpy(dst, &v, 4)`.
   Decode is the mirror image. Don't `reinterpret_cast<const uint32_t*>(src)`:
   it breaks alignment and strict aliasing.

## Varints

1. Each byte carries 7 payload bits. The high bit means "more bytes follow".
   What is the largest value that fits in one byte? In two?
2. Encode: while `v >= 0x80`, emit `(v & 0x7f) | 0x80` and shift right by 7,
   then emit the final byte. Decode: accumulate `(byte & 0x7f) << shift`
   until a byte without the high bit appears. Fail if you run out of input
   or exceed the maximum length.
3. Overflow check for u64: at `shift == 63`, only the value `0x00` or `0x01`
   is legal in the 10th byte. For u32: at most 5 bytes, and the 5th byte ≤ 0x0f.
   `GetVarint*` consumes from `input` (`input.remove_prefix(n)`) only on success.

## CRC32C (`util/crc32c.cc`)

1. CRC32C is the Castagnoli polynomial, *reflected* form `0x82f63b78`. The
   table-driven algorithm processes one byte per table lookup.
2. `table[i]` = the CRC of the single byte `i`: start with `c = i` and loop 8
   times: `c = (c & 1) ? (c >> 1) ^ poly : c >> 1`. Making that a
   `constexpr` function returning `std::array<uint32_t, 256>` puts the
   table in `.rodata` with no runtime init.
3. `Extend(init, data)`: `c = ~init`; for each byte `c = table[(c ^ b) & 0xff] ^ (c >> 8)`;
   return `~c`. Mask: `((crc >> 15) | (crc << 17)) + 0xa282ead8` (`std::rotr(crc, 15) + kMaskDelta`).
   Test vector: CRC of 32 zero bytes = `0x8a9136aa`.

## FileDescriptor

1. Which operations must never throw, and what does a throwing move
   constructor do to `std::vector<FileDescriptor>` growth?
2. Move ctor: take `other.fd_` and set `other.fd_ = -1`. Move assign:
   guard self-assignment, close your own fd, then steal. `release()` returns
   the fd and gives up ownership. `reset(fd)` closes the old one and adopts
   the new one.
3. What does `close()` returning `EINTR` mean on Linux vs macOS? (On Linux,
   the fd is closed anyway: never retry.) `Close()` reports the error.
   The destructor can't, so it ignores it, and your comment says why that's acceptable.
   `SyncFd`:
   - `kFsync`: `fsync`.
   - `kFdatasync`: `fdatasync` on Linux, `fsync` elsewhere.
   - `kFullFsync`: `fcntl(fd, F_FULLFSYNC)` on macOS; if that fails with
     ENOTSUP, fall back to `fsync`. `fsync` on Linux.
   - `kBarrierFsync`: `F_BARRIERFSYNC` on macOS, `fsync` on Linux.
   - All of them: retry on EINTR, but **never retry after EIO**.

## PosixFileSystem

1. Which calls can return short counts or EINTR? (`read`, `write`, `pread`.)
   You need loops.
2. `NewWritableFile`: `open(O_WRONLY|O_CREAT|O_TRUNC|O_CLOEXEC, 0644)`.
   Appendable: `O_APPEND` and no truncate. The writer buffers in user
   space (`writable_buffer_size`); `Flush()` drains the buffer with `write`;
   `Sync()` = `Flush()` + `SyncFd`. `SyncDir`: open the directory
   `O_RDONLY` (`O_DIRECTORY` on Linux) and fsync it.
3. `LockFile`: `open(O_RDWR|O_CREAT)`, then `flock(fd, LOCK_EX|LOCK_NB)`.
   `EWOULDBLOCK` maps to `Busy`. Why not `fcntl` locks? (They're per-process,
   so a second open in the same process "succeeds", and closing *any* fd for
   that file drops the lock.) `GetChildren` must skip `.` and `..`.
   `DefaultFileSystem()`: a function-local static (thread-safe init since
   C++11) that is intentionally leaked. Why leaked?

## STRATA_ASSIGN_OR_RETURN

1. The macro must declare a new variable in the caller's scope, e.g.
   `STRATA_ASSIGN_OR_RETURN(auto file, fs.NewWritableFile(p));`. A
   `do { } while (0)` wrapper can't do that. Why?
2. Use a uniquely named temporary (`__LINE__`/`__COUNTER__` pasting, like
   `ASSERT_OK_AND_ASSIGN` in `tests/support/test_util.h`): evaluate the
   expression into it, return early if it holds an error, then
   `lhs = std::move(*tmp)`. The puzzle is making that `return` type-check
   in both `Status` and `Result<U>` functions.
3. `return Err(std::move(tmp).error());` works for `Result<U>` callers but
   not for `Status` callers, and `return tmp.error();` is the reverse. One
   answer: return a proxy struct holding the `Status`, with
   `operator Status() &&` and `operator std::unexpected<Status>() &&`.
   `std::unexpected<Status>` converts to every `Result<U>`.
