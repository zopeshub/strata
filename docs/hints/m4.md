# M4 hints

## BlockBuilder

1. For each key, how many leading bytes does it share with the previous key?
   When do you reset that to 0?
2. If `counter_ < restart_interval`, compute `shared` = the common prefix
   length with `last_key_`. Otherwise push `buffer_.size()` onto `restarts_`,
   set `counter_ = 0`, and use `shared = 0`. Append the three varints, the key
   suffix, and the value. Update `last_key_`, and `counter_++`.
3. `Finish()`: append each restart as fixed32, then the count. Start with
   `restarts_ = {0}`. `CurrentSizeEstimate` = `buffer + 4*restarts + 4`.

## Block reader (untrusted!)

1. Before anything else: what must be true of `size` and `num_restarts` for
   the restart array to fit?
2. Constructor: `size >= 4`. `num_restarts = DecodeFixed32(end - 4)`. Check
   `num_restarts <= (size - 4) / 4` *without overflow* (divide, don't
   multiply). Otherwise the block is malformed, and every iterator reports
   Corruption. Entry decode: read three varints, then check
   `non_shared + value_len <= remaining` *and* `shared <= last_key.size()`.
3. `Seek(target)`: binary search on restarts for the last restart whose key
   (full, since `shared == 0` there) is `< target`, then scan forward to the
   first key `>= target`. `key()` returns a view into the iterator's own
   `std::string key_` (prefix-compressed keys can't be views into the block),
   and `value()` is a view into the block.

## Bloom

1. From one 32-bit hash, how do you get k "independent" probe positions?
2. `h = Hash(key, seed); delta = std::rotr(h, 15); for i < k: set bit (h % bits); h += delta;`
   Build: `bits = max(n * bits_per_key, 64)`, rounded up to whole bytes, and
   append `k`. Probe: the same loop checks bits and returns false on the
   first zero.
3. `KeyMayMatch` guards, both "maybe" (true): `filter.size() < 2` (no room
   for bits + k), and `k > 30` (reserved for future encodings). A filter
   built from zero keys is *not* malformed: it's 8 zero bytes plus k, and
   correctly answers "absent" for everything. `tests/m4/bloom_test.cc`
   checks all three.

## TableBuilder

1. Why can't you write the index entry for a data block at the moment you
   finish that block?
2. Keep `pending_index_entry_` + `pending_handle_`. When the next key comes
   (or at `Finish`), compute the separator between the last key and the new
   key, add `separator → handle` to the index block, and clear pending.
   Flush a data block when `CurrentSizeEstimate() >= block_size`.
3. `WriteBlock(contents)`: append the contents, then the trailer: `type=0`,
   `crc = Mask(Extend(Value(contents), "\0"))`. Record `BlockHandle{offset, size}`
   and advance `offset += size + 5`. `Finish` order: last data block, filter
   (over `ExtractUserKey` of every key, collected as `std::string`s since the
   blocks get reset), properties, metaindex, index, and the footer (padded to 40 + magic).

## Table reader

1. What does `Open` need to read, in which order, before any lookup can work?
2. Read the last 48 bytes → `Footer`. `ReadBlock(index)`, then
   `ReadBlock(metaindex)`, then find `filter.bloom` and `strata.properties`
   in it. Keep the index `Block`, the filter string, and the properties.
3. The two-level iterator: an index iterator. On each positioning, read the
   data block its value points to (`ReadBlock`), make a block iterator over
   it, and skip forward over empty or exhausted blocks. The iterator must
   **own** the current data `Block` (unique_ptr) because block iterators
   borrow it. `Get`: bloom on the user key → index Seek(ikey) →
   ReadBlock → Seek. Then check that the user key matches and interpret the
   type. Count stats with relaxed atomics.
